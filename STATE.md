## 1. Что за проект

**GustoPlay** (gustoplay.ru) — одностраничный сайт подбора игр по вкусу: квиз на
60 секунд → персональная выдача с объяснением «почему подходит», каталог с фильтрами,
профиль вкуса, аккаунты с синхронизацией. Билингвальный (ru/en), тёмная/светлая тема.
Заказчик дал контент-план из 10 заходов; правила: ничего не выдумывать, каждое
«сделано» — с числом/прогоном, полный набор проверок зелёный, PR держать вливаемым.

Стек: чистый JS (без сборщиков в рантайме), статическая сборка `tools/build-static.mjs`
(729 страниц с пре-рендером), API аккаунтов — Cloudflare Worker (`worker/`, D1/SQLite),
деплой — Cloudflare Pages. Тесты — свои тулзы на node + jsdom + реальный Chromium.

## 6. Как работает доставка данных (Steam закрыт из песочницы)

Всё, что требует Steam/HLTB, делается ботовскими воркфлоу GitHub Actions:

| Воркфлоу | Что делает | Триггер (push в ветку, пути) | Результат |
|---|---|---|---|
| `catalog-batch.yml` | Steam appdetails + reviews + HLTB по списку кандидатов | `tools/catalog-candidates.json` и др. | коммит `tools/catalog-batch-data.json` + review.txt |
| `covers.yml` | обложки (steamId → library_600x900) и, следом, store-ссылки | `js/catalog/part-*.js` | коммит `js/catalog/steam-covers.js` |
| `sysreq.yml` | минимальные/рекомендуемые требования к ПК | `tools/pull-system-requirements.mjs`, `sysreq-format.mjs`, `sysreq-overrides.json`, `part-*.js`, `steam-covers.js`, сам yml | коммит `js/catalog/sysreq.js` |
| `ci.yml` (тесты) + PR-воркфлоу | полный набор проверок | любой push | зелёный/красный |

**Критические правила доставки:**
- Боты коммитят в ветку → **замораживать свои пуши, пока их прогон идёт**
  (~15–22 мин), иначе non-fast-forward гонка (уже был сорванный sysreq-пуш).
- Пуши от GITHUB_TOKEN не запускают воркфлоу — PR-прогоны на бот-коммитах будут
  `action_required` и перезапускаются следующим пушем пользователя. Это норма.
- Если sysreq/covers-прогон «успешен», но коммита нет — прогон был «впустую»
  (например, steamId ещё не доставлены): нужен триггер-пуш по путям воркфлоу.
- Артефакты прогонов из песочницы не читаются (Azure blob EOF) — данные только
  через бот-коммиты.

## 7. Команды сессии (проверить всё)

```bash
npm ci                                   # окружение (после пересоздания песочницы)
npm run qa:setup                         # + Chromium для браузерных проверок
npm run test:all                         # ВЕСЬ набор (долго, ~15 мин)
npm run audit:readiness                  # обложки/описания/store/sysreq — долги каталога
npm run check && npm run check:text      # каталог + тексты ru/en
npm run backup                           # бэкап перед рискованными операциями
npm run commit                           # коммит с догоном origin (если git падал)
```

Восстановление после пересоздания песочницы (уже случалось дважды):
`git fetch origin arena/01a0e3da-gustoplay && git reset --hard FETCH_HEAD`
(незакоммиченные правки — сначала сохранить в /tmp!), затем `npm ci && npm run qa:setup`.

## 8. Правила, которые нельзя нарушать

1. **Никаких выдуманных данных**: игры, рейтинги, числа — только из проверяемых
   источников (Steam снимки в `tools/catalog-batch-data.json`, HLTB, ЦБ РФ);
   нет данных — писать «данных нет».
2. Каждое «сделано» — с числом/путём/прогоном в коммит-сообщении и отчётах.
3. Коммиты маленькие, сообщения по-русски, ветка только `arena/01a0e3da-gustoplay`.
4. Токен GitHub в песочнице периодически умирает (~1–1,5 ч) — 401 и на `gh`, и на
   `git push`: продолжать локально, ретраи каждые 30–60 с.
5. Скрипты с puppeteer запускать из корня репо (не из /tmp); Chromium —
   `/tmp/gustoplay-qa-bin/chromium` (ставит `qa:setup`).
6. Inline `node -e` с кавычками ломается — писать скрипты в файлы.
