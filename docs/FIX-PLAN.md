## Что проверяется автоматически (чтобы это не сломалось снова)

* `npm run test:visual` — реальный Chromium **с включённой мышью и hover** (у headless
  по умолчанию `hover: none`, из-за этого баг из п. 1 вообще не воспроизводился):
  стабильность раскладки кнопок отметок под курсором, отсутствие цикла наведения,
  поведение шторки на телефоне (доля экрана, крестик, Esc, затемнение, возврат фокуса),
  сдвиги макета (CLS), обрезанный текст, плюс обычный обход 17 маршрутов.
* `npm run test:css` — структурные проверки CSS: у `.mark:hover` нет правил, меняющих
  раскладку; подпись отметки всегда визуально скрыта; нет правила, возвращающего
  подпись в поток по наведению; шапка держит пункты меню в одну строку (§5б).
* `npm run check:text` — орфография и типографика RU/EN (словари офлайн), единый стиль
  английского.
* `npm run check:stores` (CI, `links.yml`) — каждая ссылка ведёт на конкретную страницу
  игры, страница живая и называется как игра; для игр без Steam — официальный магазин.
* `npm run test` (smoke) — ссылка «Открыть в Steam» ведёт на `/app/<id>/`, поисковых
  заглушек нет; `npm run test:functional` — поведение отметок, фокус, доступность подписи.

## Ограничения среды (честно)

* В песочнице доступны только GitHub и npm: Steam, Nintendo eShop, PlayStation Store,
  Epic, Google Play, сайты издателей закрыты (проверено, ответ 000). Поэтому ссылки
  в п. 4–5 проверяются в CI (`links.yml`), где сеть есть, и только после проверки
  попадают в данные. Выдуманных адресов в каталоге нет: либо подтверждённая страница,
  либо официальный сайт издателя, либо кнопки нет.
* Игр, у которых нет страницы в Steam (Nintendo-эксклюзивы, мобильные, Battle.net,
  Epic-эксклюзивы), нельзя снабдить ссылкой на Steam — для них даётся официальный
  магазин/сайт издателя.
* Живые устройства (настоящий телефон), Lighthouse и внешние CDN обложек в песочнице
  недоступны: вёрстка проверена в Chromium на 360–1920px, обложки — по данным каталога.
