# Аккаунты GustoPlay: что сделано и как включить

Сайт умеет работать **без аккаунта** (профиль вкуса в localStorage) и **с аккаунтом**
(регистрация, вход по паролю, вход через Google, синхронизация между устройствами).
Аккаунт — не обязательное условие подбора: посетитель может пройти квиз и получить
рекомендации сразу.

## Что уже в коде

| Файл | Роль |
|---|---|
| `js/views/account.js` | страница `#/account`: вход, регистрация, Google, синхронизация, сессии, удаление |
| `js/api.js` | клиент API: Bearer-токен, авто-разлогин при 401, Google Identity, Turnstile |
| `worker/index.js` | Cloudflare Worker: регистрация, вход, Google-проверка, профиль, сессии |
| `worker/schema.sql` | схема базы D1: `users`, `sessions`, `profiles`, `reset_tokens`, `rate_limits` |
| `worker/README.md` | развёртывание за 10 минут + настройка Google OAuth |
| `js/store.js` | автоотправка профиля на сервер через 4 секунды после изменения |
| `js/analytics.js` | цели воронки: `quiz_start`, `quiz_complete`, `mark_*` (Метрика — только после согласия на cookie) |
| `js/config.js` | `SITE.apiBase`, `AUTH.googleClientId`, `AUTH.turnstileSiteKey` |

## Как включить

1. Разверните Worker по инструкции `worker/README.md` (бесплатный тариф).
2. В `js/config.js`:
   ```js
   apiBase: '/api',                      // Worker на маршруте /api того же домена
   googleClientId: '…apps.googleusercontent.com',
   turnstileSiteKey: '0x4AAA…',
   ```
3. Пересоберите статику: `npm run build`.

Пока `apiBase` пуст, страница `#/account` показывает честную плашку «Сервер аккаунтов
не подключён» и предлагает пройти квиз — ничего не ломается.

## Сценарии, которые поддерживаются

**Регистрация по e-mail.** Пароль от 10 символов, проверка по базе утечек-паттернов
(«password», «qwerty» и т. п.), индикатор надёжности в интерфейсе. После регистрации
локальный профиль вкуса сразу уезжает на сервер — человек не теряет ответы квиза.

**Вход по паролю.** Единый ответ «Неверный e-mail или пароль» — не раскрываем, есть ли
такой аккаунт. Неудачные попытки считаются: 20 в час на адрес, 30 запросов в минуту на IP.

**Вход через Google (включая регистрацию одним кликом).** Кнопка Google Identity
Services рендерится на странице аккаунта. Токен проверяется на сервере полностью:
подпись RS256 по JWKS Google, `aud` = наш Client ID, `iss`, `exp`. Секрет клиента
на фронтенде не нужен.

**Привязка Google к существующему аккаунту.** Если e-mail уже зарегистрирован по паролю,
вход через Google объединяет аккаунты: почта подтверждена Google, пароль остаётся
вторым способом входа.

**Сброс пароля.** Ссылка «Забыли пароль?» на форме входа → письмо с одноразовой ссылкой
(действует час, повторная отправка не чаще 5 раз в час на адрес). Токен хранится в базе
как SHA-256 хеш, после использования гасится, а все сессии аккаунта завершаются —
если аккаунт увели, сброс пароля выкидывает чужой вход. Ответ API одинаковый для
существующих и несуществующих адресов, чтобы нельзя было перебором найти зарегистрированных.

Для отправки писем используется Resend (бесплатно до 3000 писем/месяц):

```bash
npx wrangler secret put RESEND_API_KEY    # ключ из resend.com
npx wrangler secret put MAIL_FROM         # "GustoPlay <no-reply@gustoplay.ru>"
```

Пока почта не подключена, API отвечает `{ ok: true, sent: false }` и пароль не сбрасывается —
в интерфейсе честно написано, что письмо не отправлено. Для проверки владельцем сайта можно
на время поставить `ALLOW_RESET_DEBUG = "true"` в `worker/wrangler.toml`: тогда ссылка
вернётся прямо в ответе API (на боевом домене держите `false`).

**Синхронизация вкуса.** При входе профиль подтягивается с сервера (если он там есть),
иначе локальный отправляется вверх. Дальше каждое изменение уходит автоматически
с задержкой 4 секунды, чтобы не долбить API на каждый клик.

**Сессии.** Список активных устройств на странице аккаунта, отзыв любого по кнопке.
Токен живёт 90 дней; выход удаляет только текущую сессию.

**Удаление аккаунта.** Кнопка «Удалить аккаунт» чистит `users`, `sessions`, `profiles`
на сервере. Локальный профиль остаётся в браузере, если человек не сбросит его сам —
это осознанно: подбор продолжает работать без регистрации.

**Экспорт и импорт.** Кнопки на странице «Мой вкус» — JSON-файл с ответами и отметками.
Пригодится, чтобы перенести вкус в другой браузер или просто проверить, что мы храним.

## Чего сознательно нет

- **Пароля от Apple/Facebook/VK.** Google закрывает 60–70 % аудитории, добавлять
  остальные имеет смысл после запуска — код `handleGoogle` обобщается на любого
  провайдера с OIDC за один вечер.
- **Подтверждения e-mail при регистрации.** Сброс пароля письмом уже работает (Resend),
  но верификация адреса при регистрации выключена: она снижает конверсию в первый месяц.
  Флаг `AUTH.requireEmailVerification` в конфиге есть — включим, когда увидим спам-регистрации.
- **Платных подписок.** Сначала аудитория, потом монетизация: реклама из
  `docs/MONETIZATION.md` + партнёрские ссылки на магазины.

## Юридический минимум

В политике конфиденциальности (`#/about`) уже описано: какие данные хранятся, зачем,
как удалить аккаунт, что пароль необратимо хешируется, что Google передаёт только
e-mail и имя. Для прохождения верификации Google нужны ещё:

1. страница с политикой (есть, `#/about` → блок «Политика конфиденциальности»);
2. условия использования — добавьте блок в тот же раздел;
3. контактный e-mail поддержки — `gustoplaysupport@gmail.com` (указан в `SITE.email`, выводится
   в подвале, в FAQ «Как это работает», в политике и в условиях использования).

## Что проверить перед запуском

```bash
node tools/check-catalog.mjs    # каталог цел
npm test                        # включая сценарий «аккаунт в локальном режиме»
npm run build                   # статика с пре-рендером
```

После деплоя Worker:

```bash
curl https://gustoplay.ru/api/health         # {"ok":true,…}
curl -i -X POST https://gustoplay.ru/api/auth/login \
  -H 'Content-Type: application/json' -d '{"email":"a@b.ru","password":"short"}'
# ожидаем 401 с текстом «Неверный e-mail или пароль», без деталей о базе
```
