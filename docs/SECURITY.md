# Безопасность GustoPlay

Этот документ отделяет меры, которые видны в исходниках и проверены локально, от
настроек внешней инфраструктуры. Наличие кода **не подтверждает**, что Worker,
D1, домен или правила Cloudflare сейчас развёрнуты и настроены в production.

## Что реализовано в коде

| Область | Проверяемая реализация | Доказательство |
|---|---|---|
| Пароли | PBKDF2-SHA256, 210 000 итераций, случайная соль; минимум 10 символов и проверка простых паролей | `worker/index.js`; `npm run test:api` |
| Сессии и сброс пароля | Случайный bearer-токен; в D1 сохраняется только SHA-256; срок сессии 90 дней. Ссылка сброса одноразовая, 60 минут; после смены пароля сессии отзываются | `worker/index.js`, `worker/schema.sql`; API-тесты сессии и сброса |
| Google ID-токен | Проверка RS256/JWKS, `iss`, точного `aud`, `azp` при наличии, `iat`/`exp`/`nbf`, `sub`, формата e-mail; `email_verified` обязателен. Неверные и повреждённые токены отклоняются до создания/привязки аккаунта | `verifyGoogleToken()` в `worker/index.js`; тесты в `tools/test-api.mjs` |
| Ограничение тела | JSON авторизации — до 16 КиБ; профиль — до 256 КиБ в UTF-8 плюс небольшой запас на JSON-обёртку. Повреждённый JSON → 400, превышение → 413 | `readJsonBody()` и `handleProfilePut()` в `worker/index.js`; тесты oversized, malformed и Unicode payload |
| Rate limit | Атомарный счётчик SQLite `UPSERT … RETURNING`: до 30 запросов авторизации/мин на IP, до 20 попыток входа/час на нормализованный e-mail, до 5 сбросов пароля/час на e-mail. Окно фиксированное, не скользящее. E-mail в ключе счётчика заменён детерминированным SHA-256; это псевдонимизация, **не** анонимизация. IP-ключ авторизации остаётся в открытом виде до очистки | `rateLimit()` и обработчики в `worker/index.js`, `worker/schema.sql`; тесты лимитов и отсутствия открытого e-mail в ключах |
| HTML/XSS-шаблоны | Экранированы значения карточек/профиля; URL магазина принимаются только по HTTPS; JSON-LD сериализуется без буквального `<`, чтобы строка `</script>` не закрывала элемент при пререндере | `js/views/components.js`, `js/cover.js`, `js/app.js`; payload-регрессии в `tools/test-functional.mjs` |
| CORS и браузерная авторизация | Клиент отправляет явный Bearer-токен и `credentials: omit`; API не выдаёт `Access-Control-Allow-Credentials`. CORS сверяет Origin с `ALLOWED_ORIGINS` | `js/api.js`, `worker/index.js`; API-тест preflight и запрещённого origin |
| HTTP-заголовки | Worker добавляет HSTS, `nosniff`, Referrer-Policy, запрет фреймов и Permissions-Policy; статическая сборка копирует `_headers` с CSP/HSTS и другими правилами | `worker/index.js`, `_headers`; `npm run verify:build` проверяет собранные заголовки |
| Rate-limit cleanup | В `worker/wrangler.toml` описан ежедневный cron для очистки просроченных сессий, счётчиков и токенов | Код конфигурации есть; факт запуска cron на удалённом Worker не проверен |
| Контакт для сообщения о проблеме | Сборка создаёт `/.well-known/security.txt` с существующим публичным адресом поддержки, языками ru/en, сроком действия и canonical | `tools/build-static.mjs`; проверяется `npm run verify:build` |
| Зависимости | На момент этой проверки локальный `npm audit` сообщает `found 0 vulnerabilities`; уязвимый старый CSS-пакет заменён на PostCSS, сборку CSS минифицирует esbuild | `package.json`, `package-lock.json`; `npm audit`; `tools/build-static.mjs` |

Поиск секретов в доступной Git-истории выполнен после `git fetch --unshallow origin main`:
124 коммита, 529 уникальных blob-объектов; совпадений с 8 шаблонами высокой уверенности
(private key PEM, GitHub/Google/Stripe/Resend/AWS/Slack token) нет. Это не универсальный
secret scanner: произвольные пароли или нестандартные ключи могут не совпасть с этими
шаблонами, поэтому результат не является гарантией отсутствия секретов.

Полный текущий API-набор запускался командой `npm run test:api`; фактический счёт
**69/69**. Тесты выполняются локально на SQLite-эмуляторе D1; это не интеграционный
тест против production Cloudflare D1.

## Что остаётся вне локальной проверки

- **Production Worker и D1.** `worker/wrangler.toml` содержит placeholder
  `database_id = "ЗАМЕНИТЕ_НА_ВАШ_ID"`. Доступ к Cloudflare и удалённой базе не
  проверялся; локальная сборка не подключает API.
- **Turnstile.** В `js/config.js` site key пуст. Если `TURNSTILE_SECRET` отсутствует,
  `verifyTurnstile()` намеренно пропускает проверку. Защита от ботов не считается
  включённой, пока владелец не настроит и не проверит обе стороны интеграции.
- **Google OAuth.** Client ID в `js/config.js` пуст, поэтому вход Google в локальной
  сборке отключён. Создание/публикация Google Cloud project, выдача ключей и настройка
  origin требуют отдельного согласования владельца.
- **Подтверждение e-mail.** Для регистрации по паролю подтверждение адреса не
  реализовано; `AUTH.requireEmailVerification` сейчас `false`. Это отдельная работа,
  включающая почтовый поток. Реальную отправку писем, Resend, отправителя и домен
  без согласования не настраивать.
- **Cloudflare controls.** SSL/TLS, WAF, bot rules, DDoS-настройки, production secrets,
  доступность D1-backup и фактическое расписание cron требуют проверки в панели/аккаунте.
  Конфигурационный файл не доказывает их состояние. Любая платная функция или расход
  предварительно согласуется.
- **Срок bearer-сессии — 90 дней.** Сокращение срока повлияет на пользователей и
  требует продуктового решения; тесты подтверждают структуру сессии, но не измеряют
  реальное истечение времени в production.
- **Хранилище rate limit.** E-mail bucket — неанонимизированный SHA-256 без отдельного
  секретного ключа; известный адрес можно сопоставить перебором. Требуется решить,
  нужен ли отдельный стабильный secret для HMAC и организовать его безопасную установку.
- **Резервные копии.** `npm run backup` сохраняет локальный Git/worktree; это не backup
  удалённой D1. Восстановление production D1 и проверка регулярного экспорта ещё не
  выполнялись.

## Форма поддержки — локальные гарантии и ограничения

`POST /support` доступен без аккаунта, ограничен размером JSON общим парсером и повторно валидирует имя/e-mail/тему/текст на сервере. Honeypot-запросы отбрасываются без записи лимита. Для остальных валидных запросов применяются текущие лимиты 5/IP за 10 минут и 3/нормализованный e-mail за час; e-mail хранится в таблице лимитов только как SHA-256 bucket, IP — как краткоживущий ключ лимита. Это мера ограничения злоупотреблений, не анонимизация и не замена WAF/CAPTCHA.

**Доставка выключена:** endpoint всегда отвечает `503 support_delivery_unconfigured` для валидного пользовательского обращения и не сохраняет/не пишет в лог поля обращения. Клиент формирует `mailto:`-черновик; пользователь сам решает, открывать ли почтовую программу и отправлять ли письмо. До согласования провайдера, адреса отправителя и обработки данных не подключать real email, не менять этот ответ на успешную доставку и не создавать таблицу сообщений.

## Порядок перед production

1. Владелец подтверждает домен/публикацию, сервисы и любые возможные расходы.
2. Согласовать и настроить production API, D1, Turnstile, Google OAuth и почтовый
   сервис отдельно; секреты передавать только через секрет-хранилище провайдера.
3. Владелец проверяет реальные Cloudflare SSL/WAF/rate-limit/DDoS настройки,
   D1 backup/restore и cron, затем проверка повторяется против production с безопасными
   тестовыми учётными записями.
4. Не включать real analytics/ads, не менять домен/DNS, не публиковать сайт и не
   открывать индексацию без отдельного согласования.
