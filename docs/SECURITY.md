# Безопасность GustoPlay: от взлома и от DDoS

Документ описывает, что уже зашито в код и какие настройки нужно включить в панели
Cloudflare после деплоя. Принцип: защита должна работать на бесплатном тарифе и не
мешать нормальному посетителю.

## 1. Что уже сделано в коде

| Угроза | Реализация |
|---|---|
| Кража паролей из базы | PBKDF2-SHA256, 210 000 итераций, индивидуальная соль на пользователя (`worker/index.js`) |
| Восстановление пароля из хеша | хеш необратим; сброс — единственный путь, пароль нигде не логируется |
| Кража токенов сессий | в базе только SHA-256 хеш токена: утечка дампа не даёт войти |
| Подбор пароля (brute force) | 20 неудачных попыток/час на e-mail, 30 запросов/мин на IP, 429 без деталей |
| Определение существующих аккаунтов | одинаковый ответ на «нет пользователя» и «неверный пароль» |
| Тайминг-атака на сравнение пароля | сравнение за постоянное время (`timingSafeEqual`) |
| Подделка токена Google | полная проверка подписи RS256 по JWKS, `aud`, `iss`, `exp` |
| SQL-инъекции | только параметризованные запросы D1 (`bind`), конкатенаций нет ни одной |
| XSS | пользовательские данные идут через `esc()`/`textContent`; `innerHTML` — только с нашими шаблонами и экранированными значениями |
| CSRF | авторизация по `Authorization: Bearer`, а не cookie; CORS ограничен списком доменов (`ALLOWED_ORIGINS`) |
| Кликджекинг | `X-Frame-Options: DENY`, `frame-ancestors 'none'` в CSP |
| Утечка через Referer | `Referrer-Policy: strict-origin-when-cross-origin` |
| Слишком большой payload | профиль ограничен 256 КБ, ответ 413 |
| Утечка деталей ошибок | наружу — «Внутренняя ошибка сервера», подробности только в логи Worker |
| Перехват ссылки сброса пароля | токен одноразовый, живёт 60 минут, в базе только SHA-256 хеш; после сброса все сессии завершаются |
| Перечисление аккаунтов по сбросу пароля | ответ одинаковый для существующего и несуществующего адреса, не более 5 запросов в час на e-mail |
| Аналитика и приватность | Метрика (cookie) подключается только после согласия; Plausible работает без cookie |
| Боты на формах | Cloudflare Turnstile на регистрации и входе (`AUTH.turnstileSiteKey`) |
| Слабые пароли | минимум 10 символов (конфиг `SECURITY.minPasswordLength`), проверка классов символов и словаря очевидных паролей |
| Слабый HTTP | HSTS с `preload`, никаких http-редиректов в приложении |

Заголовки безопасности для статики заданы в `_headers` (Cloudflare Pages):
CSP, HSTS, `nosniff`, `DENY`, `Permissions-Policy`. CSP уже включает домены
Google Identity, Turnstile и рекламных сетей — если реклама выключена,
`script-src` можно сузить.

## 2. Что включить в панели Cloudflare (бесплатно)

1. **SSL/TLS** → режим *Full (strict)*; включить «Always Use HTTPS» и HSTS.
2. **Security → Settings → Security Level**: *Medium* (на старте), `Bot Fight Mode` — вкл.
3. **Security → WAF → Managed Rules**: включить Cloudflare Managed Ruleset
   и OWASP Core Ruleset (в бесплатном тарифе — базовая часть).
4. **Rate limiting rules** (Cloudflare Free — 1 правило):
   - путь `/api/*`, метод POST, порог 30 запросов/минуту на IP → *Block* на 1 минуту.
   - Дополнительно на уровне Worker уже есть свой лимит, так что дублирование не мешает.
5. **Turnstile**: добавить сайт `gustoplay.ru`, виджет Managed → site key в
   `js/config.js`, secret key — `npx wrangler secret put TURNSTILE_SECRET`.
6. **Caching**: статика `js/*`, `css/*` — `Cache Everything` + Edge TTL сутки
   (в `_headers` уже стоит `immutable`), `/api/*` — bypass.

## 3. DDoS: почему это дешёво закрыть

GustoPlay — статический сайт на Cloudflare Pages плюс маленький Worker:

- **страницы** отдаются с edge-кэша, поэтому флуд на `/game/*` до нашего кода
  вообще не доходит: это трафик Cloudflare, а не наш;
- **API** масштабируется автоматически, но имеет смысл дополнительно:
  - включить *Under Attack Mode* (кнопка в панели) при аномалии — посетители
    проходят короткую проверку, сайт остаётся доступным;
  - поставить правило лимита на `/api/auth/*` (самые дорогие запросы);
  - держать Turnstile всегда включённым на регистрации и входе.
- **Стоимость атаки**: Workers Free = 100 000 запросов/сутки. При исчерпании Cloudflare
  вернёт 429/1015 — сайт продолжит открываться, потому что страницы статичны.
  Это и есть основная защита: нет единой «точки отказа», где атака уронит всё.

План на случай серьёзной атаки (порядок действий):

1. включить Under Attack Mode;
2. добавить правило блокировки по странам/ASN из логов Cloudflare;
3. включить кэширование HTML на edge (`Cache Everything`, TTL 5 минут) —
   страницы перестают зависеть от Worker;
4. при необходимости перевести `/api/*` на второй домен (`api.gustoplay.ru`)
   и блокировать его трафик отдельно.

## 4. Гигиена разработки

- Секреты — только `wrangler secret put`; в git они не попадают (проверьте перед
  коммитом: `git diff --staged | grep -iE 'secret|client_secret|password'`).
- Зависимости: единственная dev-зависимость — `jsdom`, устанавливается флагом
  `--no-save` для тестов. Прод-зависимостей нет вообще — меньше поверхности атаки.
- Внешние скрипты: Google Identity, Turnstile, реклама — все по HTTPS и указаны
  в CSP. Никаких CDN со сторонними библиотеками.
- Письма: секрет Resend — только в секретах Worker; ссылка сброса не логируется.
- Логи: не пишем e-mail, пароли, токены. В Worker логируются только трассировки ошибок.
- Резервные копии: `npx wrangler d1 export gustoplay --output=backup.sql` раз в неделю.
