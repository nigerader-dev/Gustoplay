# Хостинг, домен и инфраструктура

## Текущий статус и ограничения

В репозитории есть Cloudflare deploy tooling, но эта документация не подтверждает наличие production-площадки, домена у владельца, DNS, SSL, аккаунтов провайдеров или фактического релиза. Провайдер, доменная зона и платные опции не выбраны; цены, лимиты и условия тарифов здесь не проверены.

Домен/DNS, регистрация у хостинга, изменение конфигурации провайдера и production-деплой требуют отдельного согласования владельца. Не выполнять старые общие инструкции ниже как автоматическое разрешение на запуск.

---

## Вариант 1 (пример, провайдер не выбран): Cloudflare Pages

### Шаг 1. Репозиторий

Репозиторий уже существует и сопровождается через PR; рабочую ветку Arena нельзя заменять инструкцией `git init`/`push main`. Любая публикация выполняется только после отдельного согласования владельца.

### Шаг 2. Подключение к Pages (пример процесса, не одобрение на деплой)

Только после отдельного согласования провайдера, production-публикации и расходов можно рассматривать эту процедуру. Она не подтверждает текущую конфигурацию или пригодность сервиса.

1. Создайте/используйте одобренный владельцем аккаунт провайдера.
2. **Workers & Pages → Create → Pages → Connect to Git** → выберите репозиторий.
3. Настройки сборки:
   - Framework preset: **None**
   - Build command: `npm install && npm run build`
   - Build output directory: `dist`
4. Запуск релиза возможен только после согласования; фактический URL и время публикации заранее не подтверждены.

> Сборка этого снимка генерирует `dist/`, HTML-маршруты, `sitemap.xml`, `robots.txt`, `ads.txt`,
> `_headers` и `_redirects`; актуальное число страниц проверяйте по `npm run build` и `verify:build`.
> Это описание локальной сборки, а не разрешение публиковать результат.

### Шаг 3. Домен и DNS (не выполнялись)

Текущий canonical в исходном коде — `https://gustoplay.ru`; владение и production-настройки не проверены. Регистрация/покупка домена, изменение DNS, SSL и подключение домена к хостингу не выполнялись и требуют отдельного согласования. Актуальные цены, доступность доменов и инструкции выбранного провайдера здесь не приводятся.

### Шаг 4. Правила кеша и фолбэк

Файлы `_headers` и `_redirects` уже генерируются сборкой:
- `/js/*` и `/css/*` кешируются на год (у нас есть версионирование через имя файла при желании);
- HTML — без кеша, чтобы правки появлялись сразу;
- SPA-фолбэк `/* → /index.html 200` нужен для ЧПУ вида `/game/balatro` (History API).

### Шаг 5. Аналитика и мониторинг

- Аналитика и аптайм-мониторинг не настроены в этом репозитории.
- Подключение сторонних счётчиков, скриптов или внешнего мониторинга, а также передача им данных требуют отдельного согласования и проверки условий провайдера.

## Вариант 3: GitHub Pages

Поддерживается из коробки: процесс `.github/workflows/pages.yml` при каждом push собирает сайт
с адресом зеркала (`node tools/build-static.mjs --site-url=https://<owner>.github.io/<repo> --trailing-slash`)
и публикует его на GitHub Pages. Все canonical/sitemap/JSON-LD при этом указывают на адрес зеркала —
сайт сам канонизируется и не конкурирует с основным доменом в поиске.

Один раз: **Settings → Pages → Source: GitHub Actions** (workflow попытается включить это сам
на шаге «Включить GitHub Pages»).

Что отличается от Cloudflare Pages:
- нет SPA-фолбэка — роль фолбэка играет `404.html` (уже собирается), пре-рендеренные страницы
  отдаются как обычные файлы, а `/quiz` GitHub сам редиректит на `/quiz/` (поэтому у зеркала
  слэшевые адреса);
- нет своих заголовков (CSP/HSTS из `_headers` не работают — они остаются для Cloudflare);
- `robots.txt`/`ads.txt` живут в `/<repo>/`, а не в корне `*.github.io`; применимость этих файлов
  к конкретному зеркалу надо проверять отдельно;
- требования рекламных площадок к доменам здесь не проверены. Коммерческий провайдер и вариант
  хостинга не выбраны; реальная реклама не подключена.

## Вариант 4: VPS + nginx (когда появится backend)

Может рассматриваться только при отдельном согласовании владельца. VPS-провайдер, технические требования и актуальная стоимость не выбирались и не проверялись.

```nginx
server {
  listen 443 ssl http2;
  server_name gustoplay.ru;

  root /var/www/gustoplay/dist;
  index index.html;

  # ЧПУ: любые пути отдаём приложению
  location / {
    try_files $uri $uri/ /index.html;
  }

  location ~* \.(js|css|svg|webp|woff2)$ {
    expires 1y;
    add_header Cache-Control "public, immutable";
  }

  add_header X-Content-Type-Options nosniff;
  add_header Referrer-Policy strict-origin-when-cross-origin;
}
```

SSL: `certbot --nginx -d gustoplay.ru -d www.gustoplay.ru` (Let's Encrypt, обновляется автоматом).
