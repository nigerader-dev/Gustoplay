# SEO и трафик из поиска

Сайт-подборщик выигрывает не на главной странице, а на **длинных запросах**: «во что поиграть вдвоём по сети»,
«игры похожие на Stardew Valley», «лучший кооп на 4 человек бесплатно». Под каждый такой запрос нужна
своя страница, которую поисковик может прочитать без выполнения JavaScript.

---

## 1. Техническая база (уже сделано)

| Что | Как реализовано |
|---|---|
| ЧПУ | `/game/it-takes-two`, `/genre/rpg`, `/tag/coopfocused`, `/mode/coopOnline`, `/mood/relax`, `/platform/pc` |
| Режим адресов | History API + SPA-фолбэк (`_redirects`); если сайт открыт с диска, автоматически включается hash-режим |
| Пре-рендер | `npm run build` создаёт реальный HTML для **всех 562 страницы** (заголовок, описание, контент, JSON-LD) |
| Sitemap | `sitemap.xml` со всеми маршрутами, приоритетами и `changefreq` |
| robots.txt | закрыты только `/results` и `/profile` (приватные состояния) |
| Мета | уникальные title/description/canonical/OG на каждой странице, обновляются на клиенте при переходах |
| Микроразметка | `VideoGame` на странице игры (жанр, платформы, оценка), `WebSite` с `SearchAction` на остальных |
| Скорость | статика без фреймворков, `loading="lazy"` у обложек, фиксированные размеры картинок (нет сдвигов CLS) |
| Внутренние ссылки | каждый тег/жанр/настроение — ссылка на свою страницу; «Похожие игры» на странице игры; облака тегов на главной |
| Мобильность | адаптив до 360 px, тап-зоны ≥40 px, без горизонтального скролла |

## 2. Структура страниц и их роль

```
/                       главная — бренд + вход в подбор (запросы бренда и «подбор игр»)
/quiz                   подбор — «подобрать игру по параметрам»
/catalog                каталог — «каталог игр с фильтрами»
/mode/<id>              «во что поиграть вдвоём», «игры на 4 игрока», «кооп по сети», «PvP»
/mood/<id>              «во что поиграть, чтобы расслабиться / посмеяться / испугаться»
/genre/<id>             «лучшие шутеры», «лучшие рогалики», «игры про выживание»
/tag/<id>               «игры с коопом за одним экраном», «игры на Steam Deck», «короткие игры»
/platform/<id>          «игры на PS5», «игры на Switch для детей»
/game/<slug>            «<название игры> обзор / характеристики / где купить / похожие»
/party                  «во что поиграть компанией», «игры для вечеринки»
/about, /privacy        доверие (важно для модерации рекламы)
```

## 3. Контент-план: как получить 90 % трафика

Базовые страницы дают «скелет». Трафик приносят **длинные хвосты**. Что делать:

1. **Подборки под запрос.** Для каждой новой подборки создавайте отдельный маршрут-лонгрид
   (можно складывать в `js/views/`), где сверху — текст на 400–700 слов, а ниже — автоматический
   список игр из каталога по фильтру. Примеры запросов:
   - «во что поиграть с девушкой на двоих» → кооп 2 игрока, теги `relationship`/`cozy`, платформы pc+ps;
   - «игры похожие на Hollow Knight» → `similarTo('hollow-knight')` + пояснение;
   - «игры для слабого ноутбука с коопом» → тег `lowsysreq` + режим коопа;
   - «что поиграть на Nintendo Switch вдвоём» → `platform/switch` + `coopLocal`.
2. **Сезонность.** В распродажи Steam (июнь, ноябрь, декабрь) обновляйте подборки «что взять со скидкой»;
   добавляйте дату обновления — Google любит свежесть.
3. **Свежие релизы.** Каждая новая игра = новая страница + 3–5 связанных запросов. Приоритет: кооп и хорроры,
   там самый высокий интерес.
4. **Глубина.** На каждой странице игры 3–6 «Похожих игр» и ссылки на теги — это удерживает пользователя
   и передаёт вес по внутренним ссылкам.
5. **Уникальные описания.** Сейчас `desc` — одно предложение на двух языках. Для топ-50 игр стоит расширить
   до 3–5 абзацев (особенности, кому подойдёт, время на прохождение, с кем играть) — это самые посещаемые страницы.

## 4. Что мерить и как

- **Яндекс.Метрика** (включить в `js/config.js`): в «Поисковых запросах» смотрите, по каким фразам
  уже приходят — их и расширяйте.
- **Google Search Console**: запросы, CTR, средняя позиция; отдельно проверяйте «Покрытие» —
  все 562 страницы должны быть проиндексированы (проверьте через «Проверка URL» для 5–10 примеров).
- **PageSpeed Insights**: цель — LCP < 2.5 c, CLS < 0.1, INP < 200 мс. Статика с локальными SVG-обложками
  уже даёт хорошие показатели; следите, чтобы рекламные блоки не сдвигали контент (задавайте им фиксированную высоту).
- **Метрики продукта**: конверсия «визит → пройденный квиз», «визит → отметка игры», страниц на визит.
  Эти же метрики равны деньгам: больше глубины → больше показов рекламы.

## 5. Ссылки и внешние сигналы

- Ответы по делу в r/ShouldIbuythisgame, r/coopgaming, r/GameDeals — со ссылкой на конкретную подборку.
- Комментарии в тематических Telegram-чатах и Discord-серверах (без спама: помогайте, потом ссылка).
- Гостевые заметки в игровых блогах и DTF/Хабр (например, «как мы написали движок подбора игр» —
  техническая статья, которая тоже приводит трафик и ссылки).
- Steam-куратор со ссылкой на сайт в описании.

## 6. Чего не делать

- Не копировать обзоры и тексты других сайтов (уникальность = и SEO, и модерация рекламы).
- Не делать «пустых» страниц-клонов без собственного текста (Google это называет thin content).
- Не покупать ссылки и не участвовать в ссылочных сетях.
- Не перегружать страницы рекламой: 3 блока максимум, иначе падают Core Web Vitals и позиции.

## 7. Быстрый чек-лист после деплоя

- [ ] В `js/config.js` заменён домен (`SITE.url`) — от него зависят canonical и sitemap.
      Для зеркала на GitHub Pages домен задаётся флагом сборки `--site-url=…` (см. docs/DEPLOY.md, § 6).
- [ ] `npm run build` прошёл, в `dist/sitemap.xml` все страницы, `robots.txt` открыт по URL.
- [ ] Search Console: добавлен домен, загружен sitemap, проверены 5 URL на «Проверку URL».
- [ ] Метрика/Plausible включены, цели настроены (квиз завершён, отметка игры, переход в магазин).
- [ ] Проверены title/description первых 10 страниц: они уникальны и содержат ключевые слова.
- [ ] Через 2 недели — оценка позиций по 20 целевым запросам и правка контента по факту.
