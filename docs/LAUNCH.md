# GustoPlay: чек-лист запуска

Один документ, по которому сайт доводится до рабочего состояния и начинает приносить
деньги. Порядок шагов выбран так, чтобы каждый следующий имел смысл: сначала домен
и статика, потом аккаунты, потом монетизация, потом трафик.

---

## Шаг 0. Проверка перед выкладкой (5 минут)

```bash
cd <папка репозитория>
npm ci
npm run test:all     # каталог + интерфейс + API аккаунтов + сквозной сценарий
npm run build        # 625 пре-рендеренных страниц → dist/
npm run verify:build # метаданные, ссылки, sitemap, CSP, PWA
```

Ожидаемо: `Проблем: 0`, семь зелёных наборов тестов (smoke + 84 + 16 + 38 + visual + 55 + 20 проверок),
`пре-рендер 625 страниц`. Если что-то красное — не деплоить.

## Шаг 1 и 2. Домен, хостинг и аккаунты — одной командой (~10 минут)

```bash
cd <папка репозитория>
cp worker/.dev.vars.example worker/.dev.vars   # впишите Google Client ID и ключ Resend (необязательно)
CLOUDFLARE_API_TOKEN=... CLOUDFLARE_ACCOUNT_ID=... npm run deploy
```

Скрипт сам: создаёт базу D1 `gustoplay` и применяет схему → добавляет маршрут `/api/*` →
заводит Turnstile → собирает сайт с адресом API → загружает секреты → публикует воркер
и сайт в Cloudflare Pages → подключает домен и DNS-запись.

Без терминала: добавьте `CLOUDFLARE_API_TOKEN` и `CLOUDFLARE_ACCOUNT_ID` в
Settings → Secrets and variables → Actions, и вкладка Actions → «GustoPlay — деплой в Cloudflare» → Run workflow.
Дальше каждый push публикуется автоматически, но только после зелёных тестов.

Домен: купить `gustoplay.ru` у аккредитованного регистратора зоны `.ru` (reg.ru, nic.ru,
timeweb) — Cloudflare Registrar такие зоны не продаёт. Дальше деплой сам добавит домен
в аккаунт Cloudflare и напечатает в лог NS, которые надо прописать у регистратора.
После переноса NS маршрут `/api/*` и адрес сайта подключаются сами — повторным запуском
`npm run deploy` (или просто следующим пушем в master).

Ручная проверка после деплоя:

```bash
curl -s https://gustoplay.ru/api/health     # {"ok":true,...} — аккаунты живы
curl -sI https://gustoplay.ru/ | head -3    # 200 + strict-transport-security
```

Файл `_headers` из сборки уже отдаёт CSP, HSTS и правила кэша — проверьте
`https://securityheaders.com` (ждём A и выше).

Подробно, включая разбор ошибок: [docs/DEPLOY.md](DEPLOY.md) и [docs/HOSTING.md](HOSTING.md).

Проверка после деплоя:

```bash
curl https://gustoplay.ru/api/health                    # {"ok":true}
# регистрация, вход, Google, сброс пароля — вручную в браузере
```

Подробнее — [docs/ACCOUNTS.md](ACCOUNTS.md). Защита от взлома и DDoS —
[docs/SECURITY.md](SECURITY.md) (там же настройки панели Cloudflare: WAF, Bot Fight Mode,
rate limit на `/api/*`, Under Attack Mode).

## Шаг 3. Аналитика (бесплатно)

В `js/config.js`:

```js
ANALYTICS: { plausibleDomain: 'gustoplay.ru', yandexMetrika: '12345678' }
```

Что уже размечено: `pageview` в SPA, `quiz_start`, `quiz_complete`, `mark_liked`,
`mark_played`, `mark_wishlist`, `mark_disliked`. Это воронка «зашёл → прошёл квиз →
получил подборку → отметил игру».

Метрика подключается только после согласия на cookie; Plausible (без cookie) — сразу.

## Шаг 4. Реклама (РСЯ + AdSense)

1. **Яндекс.РСЯ**: заявка на `partner.yandex.ru` → сайт проверяют вручную
   (нужны: уникальный контент, политика конфиденциальности, контакты). После одобрения
   получить `R-A-…` и блоки для слотов `home-top`, `results-inline`, `game-side`, `catalog-inline`.
2. **Google AdSense**: заявка на `adsense.google.com` → тот же набор требований,
   плюс удобная мобильная версия и отсутствие запрещённого контента (у нас его нет).
3. В `js/config.js`: `ADS.mode = 'both'`, вписать `clientId`/`client`, `adsTxt`
   (полученные строки для `ads.txt`), затем `npm run build` — `ads.txt` соберётся сам.
4. Правила, которые уже соблюдены в коде: не более 3 блоков на страницу,
   нет рекламы на `/quiz` и `/account`, скрипты грузятся только после согласия.

Подробнее — [docs/MONETIZATION.md](MONETIZATION.md) (включая партнёрские ссылки и оценку дохода).

## Шаг 5. Поисковики и трафик

1. **Google Search Console**: добавить домен, отправить `sitemap.xml`, проверить
   индексацию 625 страниц; `noindex` уже стоит на персональных `/results`, `/profile`, `/account`.
2. **Яндекс.Вебмастер**: то же + «Переобход страниц» для свежих игр.
3. Через 2–4 недели: посмотреть в Метрике, какие страницы дают переходы, и усилить контент там
   (описания игр, подборки по жанрам и настроениям — [docs/SEO.md](SEO.md)).
4. Контент-канал: 1–2 страницы-подборки в неделю («во что поиграть вчетвером онлайн бесплатно»,
   «короткие хорроры на вечер») — они цепляют длинные запросы и хорошо индексируются.

## Шаг 6. Что улучшать после запуска

Порядок по соотношению «эффект / трудозатраты»:

1. **Подтверждение e-mail при регистрации** — флаг `AUTH.requireEmailVerification` уже есть,
   почта через Resend настроена на шаге 2.
2. **Экспорт статистики воронки** в админ-страницу (простой Worker-роут на своём аккаунте):
   сколько людей доходит от квиза до отметки игр.
3. **Расширение каталога** — часть I довела его до 436 игр; дальше добавляйте по темам,
   которых не хватает (следите за отчётом `npm run check`: тонкие жанры видны в статистике).
4. **Партнёрские метки Steam** — `SITE.affiliates.steam` в конфиге (сторонние перепродавцы не используются).
5. **PWA-установка** — манифест и service worker уже есть; можно добавить кнопку
   «установить приложение» и push-уведомления о новых подборках.
6. **A/B-тесты квиза** — какие вопросы чаще приводят к отметке «понравилось».
