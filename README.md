# 🎮 GustoPlay — умный подбор игры

Сайт, который подбирает игру под конкретного человека: спрашивает о настроении, компании, платформе,
времени, сложности и бюджете, а потом выдаёт список с объяснением, **почему** каждая игра подходит.
Отмечаете то, во что уже играли — веса вкуса пересчитываются, и выдача меняется на ходу.

Работает как **чистая статика**: без сборщиков, без backend, без npm-зависимостей в рантайме.
Это даёт мгновенную загрузку, бесплатный хостинг и отсутствие расходов на сервер.

## Быстрый старт

```bash
cd gustoplay   # корень этого репозитория
npm ci                                        # зависимости нужны для сборки и тестов
node server.js                                # сайт → http://0.0.0.0:5173
npm run dev:accounts -- --dir=dist            # сайт + настоящие аккаунты (нужен Node 22+)
```

Второй вариант поднимает сайт вместе с API: регистрация, вход, сброс пароля и синхронизация
профиля вкуса работают по-настоящему, данные лежат в `.data/gustoplay.sqlite`.

Полезные команды:

```bash
npm run check        # валидация каталога: дубли, неизвестные теги, покрытие
npm run audit        # полнота каталога: сколько игр по жанрам, режимам, настроениям
npm run test         # интерфейс (jsdom): квиз, выдача, отметки, страницы
npm run test:api     # API аккаунтов на реальной базе SQLite (55 проверок)
npm run test:e2e     # сквозной сценарий: сайт → /api → воркер → база (20 проверок)
npm run test:all     # всё вместе
npm run build        # сборка dist/: 625 страниц, sitemap, ads.txt, заголовки
npm run verify:build # проверка собранного сайта: метаданные, ссылки, CSP, PWA
npm run deploy:check # что готово к публикации, чего не хватает
npm run deploy       # публикация в Cloudflare: база, API, домен, сайт
npm run preview      # локальный просмотр собранного dist/
```

## Как это работает (алгоритм)

1. **Ответы квиза** дают базовые веса: настроения ×3, жанры ×2.5, «что важно» ×2, запреты ×−6.
2. **Отметки игр**: «понравилось» +1.6 к тегам игры, «не понравилось» −1.8, «хочу» +0.9, «играл» +0.15.
3. **Жёсткие фильтры**: режим, число игроков, платформы, время до финала, бюджет и список запретов
   (микроплатежи, тайм-гейты, гринд, хардкор, хоррор, катсцены, 50+ часов, PvP-only).
4. **Скоринг**: совпадения по тегам (главный сигнал), жанрам, настроениям, режимам + качество,
   длина, цена, сложность и штраф за уже показанное.
5. **Защита от однообразия**: не больше двух игр одного главного жанра в топе, штраф за повторы.
6. **Объяснения**: карточка показывает, какие именно ваши ответы и отметки её подняли.

Логика полностью детерминирована (seed + профиль), легко тестируется и не зависит от сервера.

## Как добавить игру

Каталог лежит в `js/catalog/part-a.js … part-i.js`, всего **437 игр**. Формат записи:

- `part-a…part-d` — подробный объект (пример ниже);
- `part-e…part-i` — компактный позиционный конструктор `g(...)` из `js/catalog/dsl.js`
  (порядок аргументов описан в его шапке). Так файлы остаются читаемыми при сотнях записей.

Правило: добавляйте и правьте записи **целиком** (`write_file`/точечная правка) — массовые
скрипты, пересобирающие вызовы `g(...)`, ломают записи, потому что позиции аргументов
сдвигаются. Проверка после правки: `node tools/audit-catalog.mjs` и `npm run check`.

```js
{
  t: 'Название', y: 2025, dev: 'Студия',
  gr: ['shooter', 'action'],                  // жанры из taxonomy.GENRES
  tg: ['coopfocused', 'loot', 'difficult'],   // теги из taxonomy.TAGS — это «атомы вкуса»
  md: ['solo', 'coopOnline'], pl: [1, 4],     // режимы и диапазон игроков
  pf: ['pc', 'ps'], pr: 'mid', pv: 2490,      // платформы, ценовая категория, цена в ₽
  len: [20, 60], dif: 4, pace: 4, rat: 88,    // часы до финала/на 100%, сложность, темп, рейтинг
  mood: ['adrenaline', 'laugh'], coopQ: 9,    // настроения и «насколько хороша в компании»
  desc: { ru: 'Одно предложение.', en: 'One sentence.' },
}
```

## Аккаунты и безопасность

- Аккаунты (регистрация, вход по паролю, вход через Google, синхронизация вкуса,
  список сессий, удаление аккаунта) — [docs/ACCOUNTS.md](docs/ACCOUNTS.md);
  код: `js/views/account.js`, `js/api.js`, `worker/`.
- Защита от взлома и DDoS, заголовки CSP/HSTS, Turnstile и rate limit —
  [docs/SECURITY.md](docs/SECURITY.md), заголовки в `_headers`.
- Пока `SITE.apiBase` пуст, сайт работает в локальном режиме: профиль вкуса живёт
  в localStorage, страница `#/account` показывает объяснение, ничего не ломается.

## Как работает подбор

`js/engine.js` — движок v2: веса по тегам с IDF-поправкой (редкие теги весят больше),
косинусная похожесть на отмеченные игры («похожа на Hades»), мягкие предпочтения из
квиза, MMR-отбор для разнообразия топа и затухающий штраф за повторы. Квиз
(`js/quiz.js`) спрашивает настроение, компанию, число игроков, время, длину сессии,
сложность, жанры, важен ли сюжет/механика/свобода/соревнование, свежесть, бюджет,
чего не хочется, и предлагает отметить любимые игры — с живым счётчиком «подходит N игр».

## Деплой

```bash
npm run deploy:check   # проверить готовность (можно без ключей Cloudflare)
npm run deploy         # развернуть всё: база D1, API, домен, сайт
```

Скрипт сам создаёт базу D1 и применяет схему, добавляет маршрут `/api/*`, заводит Turnstile,
собирает сайт с адресом API, загружает секреты, публикует воркер и сайт в Cloudflare Pages,
подключает домен и DNS. Повторный запуск безопасен — обновляет то, что изменилось.

Альтернатива без терминала: `.github/workflows/deploy.yml` — добавьте в репозиторий секреты
`CLOUDFLARE_API_TOKEN` и `CLOUDFLARE_ACCOUNT_ID`, и каждый push будет публиковаться сам
(сначала прогоняются все тесты, публикуется только зелёная сборка).

**С чего начинать выкладку:** [docs/DEPLOY.md](docs/DEPLOY.md) — развёртывание одной командой,
и [docs/LAUNCH.md](docs/LAUNCH.md) — пошаговый чек-лист
«проверка → домен → аккаунты → аналитика → реклама → поисковики» с готовыми командами.

Подробно: [docs/HOSTING.md](docs/HOSTING.md) (хостинг и домен),
[docs/MONETIZATION.md](docs/MONETIZATION.md) (реклама и деньги),
[docs/SEO.md](docs/SEO.md) (трафик из поиска), [docs/CONTENT.md](docs/CONTENT.md) (правила каталога).

## Право и данные

Обложки генерируются собственным алгоритмом, официальные арты не используются (можно подключить свои,
включив `FEATURES.realCovers`). Названия игр и фактические данные приведены в справочных целях.
Без аккаунта профиль вкуса хранится только в браузере пользователя. Если человек сам создаёт
аккаунт, на сервере хранятся e-mail, имя и профиль вкуса — исключительно для синхронизации
между устройствами; аккаунт удаляется одной кнопкой вместе со всеми серверными данными
([docs/ACCOUNTS.md](docs/ACCOUNTS.md)).
