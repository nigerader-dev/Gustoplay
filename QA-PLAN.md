# QA-PLAN — полное тестирование GustoPlay + идеальный адаптив

> Документ-задание для следующей сессии. Цель: **ноль практических и ноль визуальных багов**,
> сайт **выглядит шикарно на любом устройстве**: телефон, планшет, ноутбук, десктоп.
> Исполнитель следующей сессии обязан пройти весь план, исправить всё найденное
> и отчитаться по форме из раздела 7.

**Контекст проекта:** чистая статика (SPA без сборщика), 437 игр, 16 маршрутов, 11 представлений
(`js/views/`), дизайн-система в `css/styles.css` (586 строк, светлая/тёмная тема, ru/en).
Базовый QA-контур уже зелёный (`npm run test:all`, `build`, `verify:build` — см. `docs/LAUNCH.md` Шаг 0).
Этот план — следующий уровень: ручное + полуавтоматическое тестирование **всего**,
с акцентом на поведение в браузере и адаптивную вёрстку.

**Как запускать сайт для проверки:**

```bash
npm ci
node server.js                       # http://0.0.0.0:5173 — обычный режим
node --experimental-sqlite tools/local-api-server.mjs   # режим с аккаунтами (Node 22+)
```

## 1. Функциональное тестирование (практика: всё должно работать)

Пройти **вживую в браузере** (через Live Preview), не только через jsdom. Легенда серьёзности:
🔴 блокер · 🟡 заметно · 🟢 мелочь.

- [ ] Карточки игр (≥3): клик открывает `/game/<slug>`, обложка-SVG на месте, нет битых картинок.
- [ ] Рекламный слот-заглушка не ломает сетку, не перекрывает контент.
- [ ] Переключатель темы (светлая/тёмная): применяется мгновенно, выбор переживает перезагрузку.
- [ ] Переключатель языка (ru/en): весь интерфейс переводится, описания игр — на выбранном языке,

### 1.2. Квиз `/quiz` (15 вопросов, ядро продукта — тестировать тщательнее всего)

- [ ] Все 11 вопросов показываются по порядку, ветвление работает:
  - соло → нет вопросов про компанию; кооп/мультиплеер → есть вопросы про число игроков и «с кем играете».
- [ ] Живой счётчик пула (`.quiz-pool`): число меняется при ответах, при пустом пуле — предупреждение,

- [ ] Кнопки «Назад/Далее»: состояние ответов не теряется при возврате.
- [ ] Мультивыбор (настроения, жанры): подсвечивается `.opt.on`, повторный клик снимает выбор.
- [ ] Вопрос «во что играли»: поиск/выбор игр работает, отметки сохраняются.
- [ ] Кнопка «Показать результат» активна только когда можно; ведёт в `/results` с непустой выдачей.
- [ ] Обновление страницы посреди квиза: либо состояние восстановлено, либо корректный рестарт (без белого экрана).
- [ ] Прямой заход на `/results` без ответов: понятное состояние («пройдите квиз»), а не пустота/ошибка.

### 1.3. Результаты `/results`

- [ ] Разнообразие: нет >2 игр одного главного жанра подряд в топе (защита от однообразия).
- [ ] Кнопки отметок на каждой карточке («играл / понравилось / не понравилось / хочу»):

- [ ] Перезагрузка страницы: отметки и выдача на месте (localStorage).
- [ ] Пустой результат (жёсткие фильтры всё отсекли): дружелюбный экран с советом ослабить фильтры,

### 1.4. Каталог `/catalog` + пресеты (`/genre/*`, `/tag/*`, `/mode/*`, `/mood/*`, `/platform/*`)

- [ ] Поиск: находит по названию (ru/en), регистронезависимо, по части слова; пустой запрос = все игры.

- [ ] Кнопки отметок работают так же, как в результатах, состояние синхронизировано между страницами.

### 1.8. Аккаунт `/account` (два режима)

Без API (локальный режим):

- [ ] Страница открывается, видно объяснение локального режима, ничего не падает.

С API (`tools/local-api-server.mjs`):

- [ ] Регистрация → сразу вход, токен в браузере, пользователь в базе, пароль хранится как хеш.

- [ ] Индикатор надёжности пароля (`.pw-meter`) реагирует на ввод.
- [ ] Кабинет: имя/e-mail, список сессий, кнопка выхода (чистит токен и сессию в базе).
- [ ] Автосинхронизация: отметка игры → через ~4 сек профиль в базе; чистый браузер + вход →

- [ ] Удаление аккаунта: подтверждение → удалены пользователь, сессии, профиль; токен мёртв.
- [ ] Выход → показывается форма входа, а не регистрация.

- [ ] About: «как это работает», контакты, политика конфиденциальности — всё на месте.

### 1.10. Сквозные сценарии (end-to-end вручную)

- [ ] **Новичок:** главная → квиз (кооп, 4 игрока) → результаты → 2 отметки → выдача изменилась →

## 2. Визуальные баги (глазами: ничего не должно «плыть»)

Проверить на **каждой** странице из раздела 1 (минимум: `/`, `/quiz`, `/results`, `/catalog`,
`/game/balatro`, `/party`, `/profile`, `/account`, 404) в обеих темах и обеих локалях:

- [ ] Нет горизонтального скролла на любой ширине (тело страницы не шире вьюпорта).
- [ ] Шапка: логотип, навигация, иконки темы/языка не налезают друг на друга, sticky работает,
      контент не прячется под шапкой при скролле и при якорях.
- [ ] Типографика: заголовки не обрезаются, длинные названия игр/жанров переносятся красиво
      (без вылезания за карточку), `h1` один на страницу.
- [ ] Карточки игр: одинаковая высота в ряду, обложки одного формата, текст не переполняет,
      кнопки отметок видны целиком и не прыгают при наведении.
- [ ] Кнопки/инпуты/селекты:стояния default/hover/focus/active/disabled выглядят осмысленно;
      `:focus-visible` заметен (доступность с клавиатуры).
- [ ] Формы аккаунта: поля, табы «вход/регистрация», pw-meter, ошибки валидации — ровно, без скачков.
- [ ] Гистограмма профиля: подписи не обрезаются, столбцы пропорциональны.
- [ ] Квиз: опции одинаковой высоты в сетке, `.quiz-pool` не дёргается при пересчёте.
- [ ] Тёмная тема: контраст текста ≥ 4.5:1 на глаз (проверить мутированные/подсказочные цвета
      `--text-muted`, `--warn-soft`, `--danger-soft` — частые нарушители), SVG-обложки читаемы.
- [ ] EN-локаль: более длинные строки не ломают кнопки/шапку/табы.
- [ ] Иконки/эмодзи жанров и настроений отображаются везде одинаково (не «пустые квадраты»).
- [ ] Toast-уведомления показываются и исчезают, не перекрывая CTA.
- [ ] Состояния загрузки/пустоты: нигде нет «голого» пустого экрана или вечного спиннера.
- [ ] Print-friendly минимум: страница игры при печати не превращается в кашу (опционально 🟢).

### 3.2. Текущее состояние (известно из кода — проверить и улучшить)

Сейчас в `css/styles.css` всего **3 брейкпоинта** (1080 / 900 / 640) — этого мало для «шикарно везде».
Известные слабые места, которые следующая сессия обязана закрыть:

1. **Нет бургер-меню**: на 640px навигация просто уезжает вниз скроллом (`.nav { order: 3 }`).
   → Сделать полноценное мобильное меню (бургер + выдвижная панель), доступное с клавиатуры.
2. **Hero-art скрыта на мобиле** (`.hero-art { display: none }`) — вместо «шикарно» пустота.
   → Заменить на компактную мобильную композицию, а не прятать.
3. **Фильтры каталога** на мобиле становятся обычной простынёй (`.filters { position: static }`).
   → Свернуть в раскрывающуюся панель/кнопку «Фильтры» с бейджем числа активных.
4. **Сетка карточек** `minmax(150px, 1fr)` на 360px даёт 2 узкие колонки — проверить читаемость,
   возможно 2 колонки ок, но с компактной карточкой (меньше метаданных).
5. **Гистограмма профиля** `.bar-row 110px 1fr 40px` на 360px — проверить, не жмётся ли.
6. **Таблицы/строки сессий** в аккаунте — на узком экране должны перестраиваться, а не скроллиться вбок.
7. **Страница игры** `.game-hero`: 220px+1fr на планшете, 1fr на телефоне — проверить промежуточные
   640–1080 (возможна «мёртвая зона» с узкой обложкой).
8. **Квиз-опции**: на телефоне должны быть 1 колонка, крупная тач-цель (≥44px высотой).

## 4. Кросс-браузер и производительность (быстрый проход)

- [ ] Chrome + Firefox + Safari (или минимум 2 из 3 через доступные средства): ключевые страницы
      без визуальных расхождений. Особое внимание: `color-mix`, `backdrop-filter`, `clamp()` —
      при отсутствии поддержки должен быть graceful fallback.
- [ ] Консоль браузера чистая: ни ошибок, ни варнингов на всех страницах (обе темы, обе локали).
- [ ] Lighthouse (или ручной замер): LCP главной < 2.5s на эмуляции Moto G4 / 4G; CLS < 0.1;
      проверить, что SVG-обложки и слоты рекламы не сдвигают вёрстку.
- [ ] `prefers-color-scheme`: при первом визите тема по умолчанию разумна.

## 6. Порядок выполнения в следующей сессии

1. Подготовка (15 мин): `npm ci`, поднять сервер, открыть превью, убедиться, что базовый
   контур зелёный (`npm run test:all`).
2. Функционал (раздел 1): идти по подпунктам 1.1→1.10, каждый чекбокс — ✅/❌ + комментарий.
   Баги чинить **сразу**, а не списком в конце (пока контекст горячий).
3. Визуал (раздел 2): проход по страницам × темы × локали.
4. Адаптив (раздел 3): ширины по нарастающей, 360 → 1920; сначала чинить структуру
   (бургер, фильтры, hero), потом полировку.
5. Кросс-браузер/перф (раздел 4): быстрый проход.
6. Автотесты (раздел 5): закрепить все фиксы регресс-тестами.
7. Отчёт (раздел 7): `docs/QA-REPORT.md` + коммит + пуш.

**Правила работы:**

- Один баг = один фикс + одна перепроверка + (если возможно) один автотест.
- Не ломать существующее: после каждого блока — `npm run test:all`.
- Не коммитить `dist/`, `.data/`, скриншоты тяжелее 300KB/шт (жать или уменьшать).
- Масштабные правки CSS — через переменные дизайн-системы, а не магические числа в 10 местах.
